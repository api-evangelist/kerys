# kerys.software — llms.txt

> TL;DR — Kerys Software builds YS::Desktop, a Type 1 hypervisor trusted by Europe's most critical and regulated organizations — aerospace & defense, energy, finance, construction, public sector — to run multiple fully isolated environments on a single workstation, replacing dedicated admin machines, air-gapped OT laptops, and traditional VDI. By running the hypervisor and VM workloads on physically separate CPU cores, YS::Desktop closes the door on VM escape and cross-VM attacks, while maintaining 92% native performance and meeting NIS2, IEC 62443, and ANSSI guideline requirements.

### 3.2 Platform & features (Products)
- [True VM Isolation – Hardware-Level Security (Secure Virtualization)](https://www.kerys.software/products/secure-virtualization): Core hypervisor security architecture. Resource preallocation (fixed CPU/memory per VM before runtime, eliminating exploitable dynamic-allocation timing signals), dedicated CPU cores for hypervisor vs. VM workloads (closing VM-to-hypervisor escape vectors), hypervisor-layer encryption of data leaving the CPU toward RAM/storage, and smart data routing (direct hardware pass-through for GPU/USB, encrypted exchange buffers for SSD/network) — all while maintaining ~92% native performance.
- [Endpoint Management – Granular Control at Scale](https://www.kerys.software/products/endpoint-management): Security Domain architecture with a mandatory-isolation model (no unmanaged VMs), a centralized management console (YAC) for fleet-wide policy deployment, granular USB/webcam/card-reader permissions, cryptographic pre-authentication per domain, configurable network modes, and dynamic context-aware policies (auto-VPN on remote work, webcam blocking in restricted zones via NAC detection), applied instantly with no reboot.
- [Network Capabilities – VMs That Run Locally](https://www.kerys.software/products/network-capabilities): VMs execute locally on the workstation instead of a remote VDI server, so network traffic never scales with headcount (0€ incremental WAN cost per added user, versus up to 20 Mbps/user and up to 2 Gbps guaranteed throughput for a 100-user VDI site). Supports NAT mode (VMs share host IP, hidden from network) and Bridge mode (each VM gets its own IP, visible as a physical device), full 802.1Q VLAN tagging that follows the VM rather than the port (NAC/802.1X compatible), and hypervisor-layer VPN enforcement triggered automatically by posture/policy.

### 3.3 Solutions (by audience)
- [For IT Teams – Virtualized Admin Workstations](https://www.kerys.software/solutions/for-it-teams): Replaces dedicated physical admin workstations (a NIS2-recommended practice) with virtualized, isolated admin environments on a single endpoint — hardened VMs, strict USB/network controls, distinct credentials, and SOC-exportable audit trails — cutting hardware costs and device-juggling while achieving NIS2 compliance and secure remote/hybrid administration.
- [For Maintenance Teams – Field-Ready Workstations](https://www.kerys.software/solutions/for-maintenance-teams): Gives OT/industrial field technicians multiple isolated environments on one device instead of three separate machines (maintenance, admin, daily use). Works fully offline, updates remotely from a central fleet console, connects directly to PLCs/SCADA via Bridge mode with manual IP assignment, and supports PKI-based trusted authentication — meeting IEC 62443 and NIS2 requirements for critical infrastructure operators.
- [For Developers – Admin Rights Without the Risk](https://www.kerys.software/solutions/for-developer): Gives each developer a secure IT-locked corporate environment plus as many full-admin-rights development environments as needed, fully isolated at the hypervisor layer — so a compromised dev environment can never move laterally to the corporate VM or network. Centralized per-environment policy, one-swipe switching at near-native performance, and automatic hypervisor-level audit trails.
